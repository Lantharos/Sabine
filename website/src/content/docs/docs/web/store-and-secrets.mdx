Every app gets a store for values it keeps between runs, such as settings, and a place for
secrets, such as tokens. Both belong to the app's id, and both work from Rust and from the app's
pages.

## The store

The store holds JSON values by key, in `store.json` in the
[app data folder](/docs/web/resources-and-files/#the-app-data-folder).

```rust
use sabine::Store;

let store = Store::open("com.example.notes");
store.set("theme", "dark")?;
let theme: Option<String> = store.get_as("theme")?;
store.on_change(|change| println!("{} changed", change.key));
```

```ts
import { events, store } from "@lantharos/sabine";

await store.set("theme", "dark");
const theme = await store.get<string>("theme");
events.storeChanged(({ key, value }) => applySetting(key, value));
```

Every window and the Rust side see the same values. Each change reaches `on_change` and
`events.storeChanged`, whoever made it. Changes are written a quarter of a second after the last
one, at most two seconds after the first, and whenever the app ends. Each write replaces the
file whole, so a crash leaves either the old file or the new one.

## Secrets

Secrets are text under a key, kept by the system:

<Tabs syncKey="platform">
<TabItem label="Linux">

The Secret Service, such as GNOME Keyring, KWallet or KeePassXC. Without one running, every call
fails and says so; Sabine never writes secrets to a file of its own.

</TabItem>
<TabItem label="Windows">

The Credential Manager, as generic credentials named `<app id>/<key>`, of up to 2560 bytes.

</TabItem>
<TabItem label="macOS">

The login keychain, as generic passwords with the app id as their service.

</TabItem>
</Tabs>

```rust
use sabine::Secrets;

let secrets = Secrets::new("com.example.notes");
secrets.set("sync-token", &token).await?;
let token = secrets.get("sync-token").await?;
```

```ts
import { secrets } from "@lantharos/sabine";

await secrets.set("sync-token", token);
const token = await secrets.get("sync-token");
```

Calls can wait while the system asks the person to unlock their keyring or keychain.

<Aside>
  On macOS, the keychain trusts the program that saved a secret. Development builds change with
  every build, so macOS asks before a new build reads an older one's secrets. A signed bundle
  keeps its identity across updates.
</Aside>

A Linux app that Sabine [confines](/docs/distribution/app-sandbox/) reaches the Secret Service
only when its `[sandbox]` talks to it:

```toml
[sandbox]
talk = ["org.freedesktop.secrets"]
```

Development runs keep their values and secrets under the development app id, apart from the
installed app's.

Store and secrets commands answer the pages the bridge trusts: the app's own and the origins it
allows.
